# Supplying the approved Quran database to CI (QR-DESIGN-006)

Status: **design only. No method is enabled and nothing has been exported or published.**

## Facts (from the approved file and the repo)

- The bundled `quran-content.sqlite` is **not in git** (gitignored) and **cannot be reproduced byte-for-byte**: it embeds `generated_at`, and the only generator (`scripts/export-content-db.mjs`) reads production Supabase, which the README says needs separate owner approval.
- Its **content** is deterministic: `content_version.overall_sha256` is a hash over the sorted Arabic ayahs, English translation rows, Kazimirski segment hashes and ayah mappings (`verify-content-db.mjs` recomputes it and pins it in `content-db.expected.json`).
- The repository is **public**. Anything committed, attached to a release or printed in a log is public. Pull requests from forks receive no secrets or variables.
- Sources (from the DB's own `content_sources`): Arabic = Tanzil Uthmani 1.1 (CC BY 3.0, attribution required, modification restricted; status `candidate`); English = Pickthall via Project Gutenberg (public domain US; `verified`); French = Kazimirski via Wikisource (public domain; `candidate`). A Hamidullah French source is `disputed` and is **not** in the bundled content.

## Fail-closed behaviour (implemented in the 006 branch)

- `release-gate` fails on pushes to `main`, `mobile-v*` tags and manual runs unless the `static` **and** `content` jobs succeeded. A skipped `content` job is a failure there.
- The `content` job runs unit tests with `REQUIRE_CONTENT_DB=1` (a missing database fails instead of skipping) and `assert-no-skips.mjs` rejects any skipped, pending or todo test, or an empty run, in both vitest and Playwright.
- To enforce the gate for merges, add "mobile release gate" as a required status check in branch protection (an owner action; `main` is not protected today).
