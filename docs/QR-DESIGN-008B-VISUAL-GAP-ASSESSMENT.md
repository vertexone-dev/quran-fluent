# QR-DESIGN-008B: screen-by-screen visual gap assessment

Reference: the five Design Lock v1.0 originals (hashes re-verified: all five match `DESIGN_LOCK_MANIFEST.json`).
Current: the combined candidate `feat/qr-design-008b`, release build (CSS-only artwork, no blocked image).
Comparison images are in the private folder `~/Pictures/QuranRoots_Design_Review_008B/` (not in git; they contain the
unlicensed originals). This file lists differences; the images are the evidence.

How to read the status column. **Matches**: same structure and treatment, judged by eye on the comparison sheets (no
pixel metric was computed). **Partial**: right idea, visible differences. **Art-blocked**: the difference is artwork whose
rights are unresolved. **Feature-blocked**: the reference shows something the product does not have, so showing it would be
fake. **Not done**: a styling or layout gap that was in scope but not achieved.

## Cross-cutting

- **Arabic RTL, English, French:** captured for Home, Reader, Settings, Memorize and Reflect on the website at desktop, tablet,
  phone and 320 px, and for the mobile screens at 390 px. No horizontal overflow was found in the 270-state sweep (008A).
- **Large text:** iPhone SE at the largest accessibility size passes the three UI tests, but the screenshots show a defect the
  tests do not catch: the French Home headline breaks inside a word ("Remonte / z à la langue."). Recorded as a remaining
  defect; not fixed here (mobile code was out of scope for this phase).
- **Not compared by number:** no automated visual-diff score was produced, because the references are composites of generated
  art and cannot be matched pixelwise.
